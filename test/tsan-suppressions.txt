# ThreadSanitizer suppressions for the extension's own code. The nightly
# ThreadSanitizer lane appends this file to the host's
# duckdb/.sanitizer-thread-suppressions.txt.
#
# The host's progress bar reads a hash join's partition mask
# (JoinHashTable::FinishedPartitionCount, src/execution/join_hashtable.cpp)
# from the client thread while a worker finalizes the join and sets bits in
# that mask. The report carries no extension frame; it appears under the
# EXCEPT ALL comparisons the tests run. Suppressing the host's race keeps the
# lane reporting races in the extension's own code.
race:FinishedPartitionCount

# DuckDB 2.0 opens an internal connection for a checkpoint that a client runs,
# taking the connection manager's lock while the client's context lock is
# held. The host also calls extension callbacks under the connection manager's
# lock when a connection closes, and when it is the last one the guard's bind
# callback (RowIdGuardBindCallback::OnConnectionClosed, src/rowid_guard.cpp)
# locks that connection's context to bind the guards in a read-only
# transaction. ThreadSanitizer joins the two orders when one connection
# checkpoints and later closes. They cannot meet: a connection cannot close
# while it runs a statement; the callback acts only when the count, read under
# the same lock, shows no other connection, so no other client can be
# checkpointing; and a read-only transaction starts no checkpoint of its own.
deadlock:RowIdGuardBindCallback::OnConnectionClosed
