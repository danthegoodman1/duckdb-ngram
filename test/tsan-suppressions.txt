# ThreadSanitizer suppressions for the extension's own code. The nightly
# ThreadSanitizer lane appends this file to the host's
# duckdb/.sanitizer-thread-suppressions.txt.
#
# The guard build takes the table's append lock in its global sink state and
# holds it for the whole build, so that the rowid baseline it records cannot
# be overtaken by a concurrent append (src/rowid_guard.cpp,
# GuardBuildGlobalInit). The host creates that state under the pipeline's
# lock and later takes the same pipeline lock again with the append lock
# still held, which ThreadSanitizer reports as a lock-order inversion. Both
# acquisitions are the build's own thread; no other thread ever waits for the
# append lock under a pipeline lock, so the cycle cannot deadlock. The host
# suppresses the same report from its own index initialization
# (deadlock:InitializeIndexes).
deadlock:GuardBuildGlobalInit
